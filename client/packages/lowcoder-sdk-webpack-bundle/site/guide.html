FROM A VISUAL APP TO YOUR PRODUCT

Put Lowcoder
inside your app.

The SDK renders Lowcoder components directly in a DOM element. Your host app controls where they live and how data moves between the two.

Start with plain JavaScript

Publish an app or module in Lowcoder and copy its application ID. Create a mount element with enough space for its layout, then load the browser SDK once.

HTML + JavaScript
<div id="customer-panel" style="min-height: 360px"></div>
<script src="https://sdk.lowcoder.cloud/bundle.js"></script>
<script>
  async function start() {
    const sdk = await LowcoderSDK.ready;
    const app = await sdk.mount('#customer-panel', {
      appId: 'YOUR_PUBLISHED_APP_ID',
      baseUrl: 'https://api-service.lowcoder.cloud',
      webUrl: 'https://app.lowcoder.cloud',
      moduleInputs: { customerId: 'customer-42' }
    });
    app.on('moduleOutputChange', console.log);
    app.on('moduleEventTriggered', console.log);
  }
  start().catch(console.error);
</script>

LowcoderSDK.ready resolves when the SDK scripts have loaded. mount() resolves after the application definition is loaded and rendering is scheduled. Individual components and queries may still be loading.

Inside a React application

The npm package provides LowcoderAppView. Install it with npm install lowcoder-sdk and import the stylesheet once in your application.

CustomerPanel.tsx
import { LowcoderAppView } from 'lowcoder-sdk';
import 'lowcoder-sdk/dist/style.css';

export function CustomerPanel({ customerId }) {
  return (
    <LowcoderAppView
      appId="YOUR_PUBLISHED_APP_ID"
      moduleInputs={{ customerId }}
      onModuleOutputChange={(output) => {
        console.log(output);
      }}
      onModuleEventTriggered={(eventName) => {
        console.log(eventName);
      }}
    />
  );
}

Use the npm package for React integration or the browser loader for a plain DOM integration. The npm release and hosted browser SDK are separate distribution channels; check your installed version before relying on newly added APIs.

Make the connection work both ways

Define inputs, outputs, events and methods in a Lowcoder module. Use those same names in your host application. A normal app can be embedded too; the module interface is what provides this explicit communication contract.

DirectionAPIUse it for
Host → moduleapp.setModuleInputs(values)Customer context, filters and other named inputs.
Module → hostapp.on('moduleOutputChange', handler)Receive the module’s current output object.
Module → hostapp.on('moduleEventTriggered', handler)React to a named event such as openCustomer.
Host → moduleapp.invokeMethod(name, args)Call a method explicitly exposed by the module after it has rendered.
app.setModuleInputs({ customerId: 'customer-99' });

const unsubscribe = app.on('moduleEventTriggered', (name) => {
  if (name === 'openCustomer') {
    // Run your host application's navigation or action here.
  }
});

// Each event has one active handler per instance.
unsubscribe();

Mount, update, clean up

Keep the returned instance while the panel is visible. Update inputs when context changes. Unmount it when your host removes that screen.

// Browser SDK
await LowcoderSDK.unmount('#customer-panel');

// Or dispose the instance directly.
app.destroy();

// Mounting again on the same element replaces its previous instance.
const next = await LowcoderSDK.mount('#customer-panel', {
  appId: 'ANOTHER_PUBLISHED_APP_ID'
});

The browser SDK reports failed downloads through the rejected ready promise and the lowcoder:error window event. Handle mount errors in your host UI so visitors see a useful retry message.

Choose your backend. Check the boundary.

Set baseUrl to your Lowcoder API origin and webUrl to your Lowcoder frontend. For workspace-specific login, pass orgId. Hosting the SDK assets elsewhere does not move your backend or change application permissions.

  • Public apps must be explicitly published and accessible to their intended audience.
  • Private apps still require authentication. Configure your API’s allowed origins and cookie settings for the host application; test the actual production domains.
  • Module inputs are client-visible context, never an authorization mechanism. Enforce access on the server.
  • The SDK shares runtime configuration and state. Use one Lowcoder deployment per host page; independent backend isolation is not supported.
  • Native embedding shares the page’s CSS and routing environment. Test typography, overlays and navigation with your host application. The SDK is not a style sandbox.
The browser loader downloads content-hashed chunks from its own location. Keep bundle.js and the complete emitted asset directory together when self-hosting. Do not concatenate, rename or selectively omit the chunks.

The landing page does not load the SDK until you start the demo. Splitting the runtime improves transfer parallelism and cache reuse; it does not by itself remove the cost of rendering components.

Already using bundle.js?

The existing .lowcoder-module-container markup continues to work, including the historically spelled locoder-backend-url and locoder-frontend-url inputs. Global opChange and onModuleEventTriggered callbacks remain supported.

<div class="lowcoder-module-container">
  <input type="hidden" class="module-id"
    value="YOUR_PUBLISHED_APP_ID">
  <input type="hidden" class="locoder-backend-url"
    value="https://api-service.lowcoder.cloud">
  <div class="lowcoder-module-display"></div>
</div>
<script src="https://sdk.lowcoder.cloud/bundle.js"></script>

For markup added after page load, call await LowcoderSDK.ready followed by LowcoderSDK.scan(). For new integrations, use the explicit mount API so ownership and cleanup are clear.
